# 管理面板实施计划

2026-10-19；设计版本2，审核通过并获用户“顺序实施、完成后统一提交”确认。main 基线 0ed32dc1dac1f51acf5f07c7b4df4d447663f6f1，唯一工作树，主代理独占实施。宿主支持 subagents，仅用于只读审核，不并行实施。顺序 P-01→P-02→P-03→P-04；多个项目共用面板和 CLI，不适合并行写入。预计工程投入 1–3 小时，中等信心，外部 CI 等待另计。

## P-01 日志、模型与目录展示

依据设计第1/3/6节。新增 logs.mjs 尾读/清除，models.mjs 结构目录与文本兼容；service.mjs/cli.mjs 提供模型结构与目录条目；dashboard 后端与前端分离日志和模型区，增加跟随、清除、已保存目录。先以缺失日志能力/目录断言失败为 Red，再覆盖追加/截断/符号链接/用户隔离/鉴权/模型来源。运行 dashboard/model/workflow 相关测试及临时浏览器。无数据迁移，恢复为现有只读日志；不清真实日志。估算20–40分钟。

## P-02 认证配置与会话隔离

依赖 P-01。依据设计第5/6节。新增认证设置公共模块验证 URL/变量及停止保存，新增 auth-sessions.mjs 迁移和指纹会话选择；engines/cli 工作区候选合并同步认证分组；ClaudeRPC、Codex 设置、doctor、setup、用户继承统一字段，model default语义统一。面板表单只显示允许字段和变量存在性。先写旧会话跨认证不得复用、失败保存旧配置、变量映射与无密钥回显测试使其失败。测试 local→api→另一地址→返回、重启反序列化别名、迁移后配置失败、忙碌锁、模型清空与环境回退。估算30–60分钟。不能回滚历史删除，因为设计保留历史；恢复用旧配置/新版本修复。

## P-03 页面创建用户与微信扫码

依赖 P-02。依据设计第4/6节。提取 pairing.mjs 为 CLI 与面板共享绑定流程，新增操作管理器负责持锁、状态、二维码、配对码、取消等待与启动；面板增创建/绑定入口；CLI 登录采用同逻辑。先用模拟API测试取消/保存竞争、二维码状态及重复名称缺失失败，再实现并覆盖提交阶段、关闭、超时/错误、启动失败与锁释放。只用临时用户与模拟服务，不代扫真实二维码。估算25–50分钟。

## P-04 整体验证、文档及交付

依赖前三项验证和独立审查。补齐 HTTP 与前端浏览器验收，更新 README/运维/认证/安全/安装文档及CHANGELOG，版本与package文件清单同步。先验证缺新模块包断言失败，再打包验证通过，全套 node --test、三平台CI。完成后单次任务提交，沿用已有GitHub发布和本机升级授权，保留服务状态。发布验证结果在最终消息区分本机/CI/真实微信。估算20–40分钟。

## 约束与完成

每项 Red→实现→focused测试→固定差异审核→verified 后进入下一项；失败回到对应范围修复。不增加无依据formatter，执行 git diff --check 和独立语义审核。共享文件按顺序累积变更，统一提交全部本任务文件，不混入其他改动。用户已明确顺序与任务级提交，无需重复询问。材料变更再回设计；实现细节直接处理。
