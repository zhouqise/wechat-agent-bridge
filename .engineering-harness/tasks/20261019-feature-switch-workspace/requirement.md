# 工作目录切换需求

## 来源与授权

任务：20261019-feature-switch-workspace。2026-10-19，用户提出“增加一个切换工作目录的功能”，并明确“以当前描述为唯一需求基线”。随后确认“微信也允许输入任意已有目录的完整路径”。上述对话是唯一需求来源。

## 目标与边界

绑定微信用户能在不重新扫码、不重复运行安装向导的情况下，将后续 AI 任务切到这台电脑上的另一个已有目录。电脑命令行及本机管理面板提供同等入口。任意已有目录不再要求事先登记，仍受操作系统访问权限与引擎自身权限约束。

用户已经明确接受每个绑定用户都可选择其他本机目录；这不是不同微信用户之间的文件系统隔离。原来的绑定身份、审批策略以及按用户保存配置保持不变。只切目录，不移动、清空或回滚项目文件。

## 可观察行为

- 展示当前工作目录；接收完整目录路径，支持包含空格和中文的路径。
- 成功后后续任务在目标目录执行；再次回到之前目录，恢复该目录对应引擎的会话。首次进入目录使用独立上下文。
- 已在运行、准备、排队、审批或回传的任务不可在中途换目录；提示用户先结束任务及清理队列。
- 无效路径、普通文件、不存在目录或切换准备失败时保留原工作目录；不自动创建目录。
- 切换只作用于当前微信用户或面板/命令行明确选择的用户；重启服务后仍使用最后成功选择的目录。
- 原有按名称切换项目的方式继续有效。

## 验收

通过临时工作区与模拟引擎验证微信、命令行、面板入口，覆盖目录 A→B→A 的执行目录和会话恢复、忙碌拒绝、错误回退、持久化、路径空格及中文、用户配置相互独立。所有测试禁止真实微信发送，不把单元测试当成真实微信端到端验证。

## 责任与待确认

wechat-agent-bridge 仓库负责微信命令、CLI、面板、配置持久化与引擎工作目录；无需修改 Codex 或 Claude Code。依据 projects.mjs、cli.mjs、wx-agent.mjs 与 dashboard.mjs 已确认仓库归属。命令名称、路径规范化及发布方式属于待审核方案，具体方案见 design.md。
