# 工作目录切换实现计划

任务：20261019-feature-switch-workspace；计划版本 1。需求见 requirement.md，设计版本 1 已通过独立复审，用户于 2026-10-19 回复“确认方案”。当前状态及选择以 status.json 为准。

## 交付目标与范围

落实 design.md 的微信、CLI 与面板目录切换，支持运行时即时生效、停止时下次启动生效，保持会话按用户、真实目录和引擎分离。目录输入、响应字段、持久化和停止竞争语义均沿用已确认设计，不在计划阶段变更。

已核实工作树为 zhouqise/wechat-agent-bridge 的 main，基线 d5feece9c29d263c314742d36ead107321845397；没有其他工作树。当前仅有本任务未跟踪工程文档，无业务代码变更。宿主具有 subagents 能力，前一阶段已用于只读设计审核；这不等于获得并行实施授权。

## 建议执行方式

建议顺序实施：P-01 → P-02 → P-03 → P-04。路径解析、在线切换、CLI/面板共用配置与入口文件，顺序验证可以减少相互覆盖及尚未验证契约的集成风险。

可选并行方式：P-01/P-02 仍须顺序，之后 CLI 和面板在独立工作树分别实现，由主代理集成并独占运行整套测试。并行需要额外拆分 P-03 的文件写入与集成安排，预期节省有限；本计划推荐顺序方式。

提交策略可选：每项验证后分别提交、全部验证后统一提交、不提交。建议全部验证后统一提交；GitHub 同步与升级继续沿用会话已有授权，提交策略本身不扩展外部发布权限。

估算为工程投入 60–110 分钟，信心中等；含测试故障注入和兼容修复，不是耗时承诺。GitHub 测试与下载等待另计。

## P-01：目录解析与停止状态保存

- 范围：projects.mjs、新增 workspace.mjs、test/workspace.test.mjs。
- 职责：projects.mjs 增加完整路径规范化、存在性/访问验证和项目配置候选生成；workspace.mjs 统一电脑入口的当前目录查询与切换路由，已运行时转发 IPC，明确停止时取得用户进程锁后重新读取配置并原子保存。
- 采用设计第3–5节，不能把 IPC 超时当成停止；不写会话文件，不执行路径字符串，不自动创建目标目录。
- 前置：计划已确认。
- 先失败验证：新增单元/文件系统测试，尚无目录解析和 workspace 入口时测试失败；覆盖非法路径、文件、缺失目录、中文/空格、真实路径与已有项目复用、重复选择、命名冲突、用户锁占用。
- 通过信号：上述断言通过；失败时配置内容不变；两个用户的配置独立；Windows 路径规则用平台参数与实际矩阵分别验证。
- 扩展：已有 projects/workflow 测试不得回归。
- 恢复：保留既有 project 功能；临时目录测试清理，失败不改真实用户配置。
- 估算：10–20 分钟。主代理实施，相关文件与临时测试资源独占。

## P-02：在线切换、会话恢复与停止协作

- 范围：cli.mjs、service.mjs、必要的 engines.mjs 适配、新增 workspace-transition.mjs 与 test/workspace-transition.test.mjs、test/workflow-daemon.test.mjs、test/users.test.mjs。
- 职责：workspace-transition.mjs 管理候选准备、会话保存、配置提交、结果发布、候选清理及可等待操作生命周期；cli.mjs 将其接到 controller/config/cwd 状态和 clean，统一微信目录命令与 admin workspace 入口，并在开始异步工作前取得 changing 状态。
- 候选状态保留既有全部会话和 tasks 引用，旧 controller 不在候选失败时被污染；同目录无操作返回。旧项目/引擎切换的公共部分只做必要适配，保留已有契约。
- service.mjs 按设计提高请求字节限额并采用 UTF-8 流式解码，保留鉴权、单行请求和现有操作限制。
- 采用设计第4–6节，依赖 P-01 验证通过。
- 先失败验证：微信目录命令和 IPC workspace 尚未实现时 A→B→A 测试失败；故障注入覆盖初始化、session 保存、配置写入/rename 前后停止及旧连接清理。
- 通过信号：实际模拟后台进程中的 cwd/threadId/重启选择正确；执行、合并、排队、审批、回传期间拒绝；初始化与配置失败后旧连接可继续；正常退出等待切换及清理完成后才释放锁；超时不重复提交。
- 扩展：模型/引擎切换、自动重连、队列、多用户与附件回传原有测试全部通过；分块中文请求和超限请求有断言。
- 恢复：按配置提交点判断恢复方向，不盲目撤销已提交目录；失败测试仅影响临时模拟实例。
- 估算：25–45 分钟。主代理独占守护进程相关文件，测试不向真实微信或模型发送请求。

## P-03：CLI 与浏览器入口

- 范围：wx-agent.mjs、dashboard.mjs、dashboard/dashboard.html、dashboard/dashboard.js、dashboard/dashboard.css、controller.mjs 帮助文本、test/dashboard.test.mjs、test/workspace.test.mjs。
- 职责：CLI 增加 workspace 查询/切换及用法错误；面板后端调用 P-01 统一路由，用户列表显示实际当前目录；前端增加路径输入和按钮，按 live/next-start 显示结果，停止状态也允许保存目录，运行忙碌时禁用切换。
- HTTP 按设计以 UTF-8 流解析及字节限额校验；仍使用原有身份、来源校验和错误兼容方式。
- 采用设计第1、3、5节，依赖 P-02 验证通过。
- 先失败验证：CLI 未知 workspace 命令、面板未支持 action=workspace 的契约断言失败；检验停止/运行/忙碌与指定用户响应。
- 通过信号：CLI 与 HTTP 的成功/失败形状符合设计，停止用户不会被自动启动，未授权请求不能修改配置，中文路径分块无损；实际浏览器可输入路径、观察成功或错误提示。
- 扩展：原有面板鉴权、模型、会话、项目和日志测试通过；临时测试用户进行浏览器交互，不切换真实用户工作区。
- 恢复：前端失败时显示原状态并允许刷新，服务端操作未知时不自动重发。
- 估算：15–25 分钟。推荐主代理顺序完成；如果用户选择并行，先明确 CLI/面板分工与独立工作树，再更新计划记录。
